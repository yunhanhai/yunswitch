# 一个渠道供 Claude Code 和 Codex 使用

共享渠道沿用原来的“统一供应商”存储及生成 ID。地址、API Key 和各客户端使用的上游协议在同一处维护；客户端仍各自选择模型、当前供应商和路由策略。

## 添加与使用

1. 在 Claude Code 或 Codex 页面选择 **添加供应商 → 共享渠道 → 添加共享渠道**。
2. 填写渠道名称、默认 API 地址和 API Key，勾选要使用它的客户端。从某个客户端进入时，默认只选择该客户端，再主动勾选另一个。
3. 分别填写模型。上游给两个客户端提供不同地址时，在该客户端的地址栏覆盖默认地址。
4. 选择上游实际提供的协议。Claude Code 原生使用 Anthropic Messages，Codex 原生使用 OpenAI Responses；选择其他受支持协议会提示需要启动 YunSwitch 本地路由并接管相应客户端。
5. 保存后，两边列表会出现关联条目。保存不改变当前供应商；在需要的客户端中分别切换到该渠道即可。

使用同一家渠道不代表两个客户端必须使用同一模型。两个客户端可同时使用该渠道，也可单独切换到别的渠道。模型列表可读不等于生成、工具调用或 Responses 协议兼容；共享渠道不会为了添加配置而自动调用上游验证。

## 修改与同步

关联条目旁显示 **共享渠道**，点击可打开共同设置。更换 API Key、地址或协议时在这里修改一次并保存。应用列表中的普通编辑仍用于模型及高级选项；地址、密钥和协议由共享渠道管理。

只更换共享密钥时，保留客户端中独立调整的模型、预算、排序、备注、路由偏好及其他高级字段。Codex 的 TOML 仅更新渠道管理的字段，保留审批策略、沙箱、MCP 和其他配置。明确在共享表单中改变某个模型字段时，该字段会同步到对应客户端。

保存时，渠道与关联数据库配置一起提交。正在使用的关联客户端随后更新实际配置；代理接管期间维护恢复来源和代理配置，不把客户端从本地代理切回上游。如果某个客户端配置写入失败，界面列出未成功的客户端，并保留输入以便重试。数据库已保存不等于客户端文件全部更新，不能把部分失败当作全部成功。

**配置预览**由后端生成，不写入、不联网，API Key 脱敏。预览用于核对生成的客户端配置；不会显示或承诺保留在其他高级设置中的所有字段。

## 停用、删除和旧配置

关闭某个客户端的开关会移除该渠道在该客户端的关联条目；删除共享渠道会移除所有关联条目。正在使用或仍被路由引用的条目会阻止移除：先切换到其他供应商并移除相关路由引用，再操作。不会自动选择替代供应商或改写用户路由顺序。

已有统一供应商保留原 ID 与关联。普通复制产生独立供应商，不继承共享关系。已经分别创建的两份普通供应商不会按相同名称、地址或密钥自动合并；本轮先完成新共享渠道与原统一供应商的可靠维护，旧条目显式关联另行处理。

API Key 仍按项目现有本地配置和客户端投影方式保存，本功能不声称只存在一份物理密钥副本，也不改变旧数据库兼容格式。官方 OAuth 和托管账号不在这项 API Key 共享范围内。跨协议转换仍受已有工具、推理、状态请求及长会话兼容边界约束。

## 验证进度

源码回归将验证双应用一次保存、更换密钥、独立端点和协议、Codex 高级配置与模型保留、预览脱敏、保存失败回滚、使用中停用/删除保护，以及部分客户端写入失败的重试。真实 Windows 验收在干净 runner 上用虚构密钥、合成数据和回环上游运行便携及升级后的 MSI，并检查实际共享入口。

当前实现与验证仍在进行，结果完成后补充。本机不读取个人客户端密钥或会话，不调用付费 API，不启动个人客户端。公开 `.8` 包保持不变；源码通过和安装包验收分开记录。
