# 流传输错误与用量观察边界

本功能已随 [Windows x64 `.9`](releases/3.20.1-yunswitch.9.md) 公开。下方保留功能开发阶段的 build-only 验收记录；公开 `.8` 原附件不变。

流输出可能持续很久。旧的用量收集器会保存所有符合筛选条件的 JSON 事件，某些上游在每个片段附带累计 usage 时，内存会随输出增长。转换器还可能把底层传输错误原文放进 SSE 错误消息。

当前开发源码对这两条路径做了限制，自动生效，不增加配置开关。查看请求结果仍使用 **设置 → 路由 → 请求诊断**；复制脱敏摘要的字段和保留期限见[请求诊断](REQUEST-DIAGNOSTICS.md)。公开 `.8` 下载包不会因源码更新而改变。

## 当前行为

- 用量观察缓冲每个 SSE 事件最多 256 KiB。超过后跳过该事件的统计观察，直到空行边界再恢复；客户端仍接收原始字节。支持跨网络片段的 UTF-8、LF/CRLF 和多行 `data:`。
- 用量收集只保留输入、输出、缓存计数和必要的模型、响应 ID。累计计数替换旧计数，Claude 的输入修正与缓存配对规则沿用既有解析器。收尾传给解析器的摘要最多 7 条；模型与响应 ID 各限 512 字节，超长值舍弃。
- 摘要不保留正文、推理、工具参数、加密历史、未知字段及无效计数原文。结束或取消时至多执行一次用量回调并释放摘要，结束后的新事件不再进入收集器。
- 代理自行生成的流传输错误使用固定英文协议消息：`stream_error` / `Upstream stream was interrupted.`，或 `stream_timeout` / `Upstream stream timed out.`。诊断分别归为响应中断和超时。错误链最多检查 16 层，不格式化底层错误原文。
- 透传路径保留错误类型，传输错误文本改为安全消息。已有的流转换路径保留各自错误终止方式，输出后不会因此自动重放。

## 使用与限制

出现失败时，在请求诊断中展开对应的本地请求编号查看安全分类和时间线。诊断摘要不包含上述用量统计的响应 ID，也不包含原始错误消息；用量记录仍沿用既有计费日志入口。

单条超大事件可能包含唯一一份 usage，跳过观察会使该请求用量缺失或不完整；不会为了统计截断客户端响应。短小但恶意伪装成模型或响应 ID 的字符串仍属于既有用量日志的元数据，本次不把旧用量日志声明为可公开分享的脱敏诊断。

本次有界范围是**用量观察缓冲与摘要**。协议转换器为工具调用、历史重建等保存的其他状态、非流式响应和既有用量日志不在这项上限之内。原生上游的语义错误正文仍按现有协议透传，不能据此宣称所有响应或日志均已脱敏。

本轮流安全验收不涵盖未识别 EOF 与总览成功计数；后续独立改动的实际进度见[请求结果与成功率](REQUEST-COMPLETION.md)。其他转换状态的上限仍待单独处理。供应商选择、用户偏好、有限重试预算、状态型 Codex 一次发送保护和默认关闭的加密历史兼容保持既有规则。

## 验证记录

源码测试覆盖长时间累计 usage、Claude 缓存配对与模型归因、OpenAI/Codex/Gemini 摘要兼容、超大无分隔事件恢复、多行和分裂 UTF-8、取消及并发收尾、合成敏感字段和输出后的传输错误。

Windows 验收脚本在干净 runner 用虚构密钥和回环上游，分别检查便携程序及升级后的 MSI：超大事件原字节交付、随后 2048 次累计 usage 的输入/缓存保留，以及四条转换路径输出后断连的安全错误、失败诊断与不重放。内存上限由源码断言验证，不用进程 RSS 推断。
