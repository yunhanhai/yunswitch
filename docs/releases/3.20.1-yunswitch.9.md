# YunSwitch 3.20.1-yunswitch.9 Windows x64 预发布准备

2026-11-27，本版正在准备，尚未公开。目标源码版本为 `3.20.1-yunswitch.9`，MSI 版本为 `3.20.1.9`；沿用 YunSwitch 独立身份、数据目录及 UpgradeCode。当前公开下载仍为 [`.8`](3.20.1-yunswitch.8.md)，原附件保持不变。

## 本版变化

本版将 `.8` 发布后分别审查、集成的改进纳入新的安装包：

- **共享渠道**：一次填写地址和 API Key，供 Claude Code 与 Codex 使用；各客户端保留自己的模型、高级设置及必要的地址和协议覆盖。已有两份配置可以通过显式预览关联，保留原 ID、当前选择及路由引用，不按密钥或地址自动合并。
- **请求诊断**：按应用和请求查看发送、输出、429 冷却、恢复排队、同家重试、备用切换及最终结果，支持并发请求与脱敏摘要；内存记录有数量、时间和事件上限。
- **请求预算与终态**：可为供应商覆盖请求预算，切换备用时预算只能收紧。诊断与总览共用一次终态结算，缺少协议终态的部分输出不再自动算作成功。
- **流错误与用量观察**：代理生成的传输错误使用安全分类；观察缓冲和用量摘要设定上限，避免无限保留流内容，原生字节透传继续保留。
- **模型目录**：按真实请求身份隔离缓存，过期结果先展示并在后台合并刷新，失败保留可用数据并退避；显式重试可立即重新加载。
- **构建来源**：关于页增加源码提交与目标平台，方便核对所运行程序和提交问题。复制的构建信息仅包含版本、源码提交（或未记录）与目标平台，不读取或复制用户配置、密钥、会话及本机路径。

上述既有功能分别完成过源码检查和 Windows build-only 验收；其中最后一次已有配置关联验收为 202 项通过。它们证明各阶段实现，不代替本次 `.9` 新包及 `.8` 升级验收。

## 使用入口

1. 新增渠道：**添加供应商 → 共享渠道**，按需启用 Claude Code 与 Codex。
2. 关联现有配置：**添加供应商 → 共享渠道 → 关联已有配置**，选择两边条目、密钥来源并预览确认。后续从条目的共享渠道入口统一维护。
3. 查看请求：**设置 → 路由 → 请求诊断**，选择应用和请求，查看等待原因、尝试过程与最终结果；复制前查看摘要包含信息的说明。
4. 核对构建：**设置 → 关于**，查看版本、源码提交及目标平台，必要时复制构建信息反馈问题。未提供构建来源的本地构建明确显示“未记录”，不会猜测提交。

共用渠道不会验证上游能力或把不同协议自动变成直连兼容。需要跨协议调用时，仍应使用已有本地路由接管。使用细节见[共享渠道](../SHARED-CHANNELS.md)、[关联已有配置](../LINK-EXISTING-CHANNELS.md)、[请求诊断](../REQUEST-DIAGNOSTICS.md)和[请求终态](../REQUEST-COMPLETION.md)。

## 使用边界

仅准备 Windows x64。发布者签名和自动更新继续关闭；macOS、Linux、ARM64 的源码测试不等于安装包验收。真实付费供应商、套餐、所有模型、长会话及用户私有数据迁移仍需逐项验证。本轮使用虚构密钥、合成配置与回环上游，不读取个人客户端密钥和会话。

自动重试继续有次数和时间上限；已有文本、推理或工具活动后不重放，状态型原生 Codex 请求保留一次发送保护。Codex 加密历史兼容默认关闭。共享渠道关联暂限明确的 API Key 配置，官方登录、间接或歧义鉴权、批量合并及关联到另一个已有共享渠道暂不支持。解除关联保留原条目和最新密钥；重新开启已解除的客户端会创建新条目，需重新关联时应显式选择原配置。

构建提交用于定位来源，不是数字签名。发布产物仍需与此记录的 SHA-256 和对应构建、验收结果共同核对。保留上游 MIT 版权、第三方许可及首页“艺の公益站”支持入口。
