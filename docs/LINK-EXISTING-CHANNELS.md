# 关联已有 Claude Code 与 Codex 配置

这项功能用于已经分别添加过同一 API 渠道的用户。它把手动选择的两条配置关联到一个新的共享渠道，后续密钥在共同设置中维护。不会根据名称、地址或密钥自动匹配，也不会重新创建两份客户端配置。

## 使用流程

1. 打开 **添加供应商 → 共享渠道 → 关联已有配置**，或从共享渠道管理页进入。
2. 分别选择已有的 Claude Code 和 Codex 配置，填写共享渠道名称，并明确选择使用哪一边的密钥。
3. 点击 **预览关联**。检查保留的地址、协议、模型和当前使用状态；密钥不显示，预览只提示两边是否不同以及哪一边将使用所选密钥。
4. 确认后建立关联。原供应商 ID、名称、模型、备注、预算、高级设置以及路由引用保留；不会切换当前供应商。
5. 后续从任一条目的 **共享渠道** 入口维护共同设置。客户端的模型和高级选项仍在普通编辑中维护。

预览不写入配置，不访问上游，也不验证付费渠道可用性。更改选择或预览过期后需要重新预览；提交时后端重新核对原配置，已变化的预览不能覆盖新的修改。

## 同步失败与解除关联

数据库中的关联一次提交，正在使用的客户端随后分别同步。若部分客户端写入失败，已保存的关联保留，界面显示需要重试的应用；使用 **重试同步** 更新同一渠道，不重复创建关联。代理接管期间继续保留代理地址并更新恢复来源，停止代理后恢复最新共享密钥。

关闭关联渠道中的某个客户端，或删除这种由已有条目建立的共享渠道，会解除对应原条目的关联，保留原条目及其路由引用。解除后使用最后保存的配置和密钥，不恢复历史密钥。原先通过“添加共享渠道”生成的条目仍遵循原有删除保护；两种来源的处理会在操作前说明。

停用并保存后，再从共享渠道打开该客户端开关会创建新的渠道条目，不会自动重新关联原配置。需要继续维护原条目时，保留它独立使用，或解除另一边后从“关联已有配置”重新选择原条目。

## 范围和限制

本轮支持把一条 Claude Code 与一条 Codex 的现有 API Key 配置关联为新共享渠道。官方登录、托管账号、已经关联的条目，以及无法明确识别鉴权来源的配置不能选择。界面会说明不可关联原因；不会读取个人客户端的额外密钥、会话或环境变量来补全配置。

当前支持 Claude 的单个 `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY`，以及 Codex 已保存的 `auth.OPENAI_API_KEY` 与选中的 TOML 连接表。多重密钥、环境变量间接鉴权、额外鉴权头、旧 bearer 覆盖和冲突的通用连接配置暂不支持直接关联；未填写的模型继续使用原来的客户端或通用默认值。已有旧统一供应商继续由原共享渠道入口维护。

两边的地址和协议可以不同，模型继续独立；共用渠道不代表模型与协议能力已验证。跨协议使用仍需已有本地路由接管。关联现有 Gemini、批量合并、加入另一个已有共享渠道和公开新版本发布不在本轮范围内。

API Key 仍按现有本地数据库和客户端配置方式保存，本功能不承诺只有一份物理副本。使用和验证均沿用 YunSwitch 独立身份与原有兼容策略。
