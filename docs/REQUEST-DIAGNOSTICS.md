# 查看本地代理的请求诊断

打开 **设置 → 路由 → 请求诊断**。启动本地代理并发出请求后，按应用筛选活跃请求和近期结果。展开任意请求，可以用本地请求编号追踪它的完整尝试过程。停止代理后仍可查看近期结果。

| 状态                     | 含义                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 正在发送                 | 代理正在读取、准备或发送请求，或等待响应到达。发送次数在每次启动上游传输时增加。                                          |
| 正在输出                 | 代理已开始向客户端转交流式数据，包括服务端事件。                                                                          |
| 等待 429 冷却            | 正在等上游的 `Retry-After`、退避或更晚的共享冷却期限。                                                                    |
| 排队等待恢复许可         | 同一应用、同一供应商的恢复尝试需要逐个进行。界面给出本阶段剩余的排队额度，实际何时拿到许可取决于前面的请求。              |
| 重试同一供应商           | 正在等退避或重新发送。同一供应商的修正重试也在这里显示。                                                                  |
| 切换备用供应商           | 代理按现有路由与故障转移策略选中另一供应商并尝试发送。                                                                    |
| 已成功、失败、取消或超时 | 请求离开活跃列表。取消详情可区分客户端断开、代理停止和已识别的上游取消。超出恢复等待额度仍沿用原有的 429 或备用转移结果。 |

时间线中的计划等待是当时安排的等待时长。实际耗时取自代理单调时钟。共享冷却延长时会新增一步，分别记录前一次实际等待和更新后的计划。请求结束时间反映代理交付响应的进度。对可识别的明文 SSE 错误事件和已知传输错误，诊断会记为失败或超时，即使客户端先收到 HTTP 200。对于未识别的协议终态、超出检查上限的事件、仍为压缩形式的响应和非标准错误信封，结果以代理看到的 HTTP 状态和流结束情况为准。

## 复制单次请求的脱敏摘要

展开请求，选择 **复制脱敏摘要**。JSON 包含本地请求编号、应用、开始时间、相对步骤时间、尝试次数、供应商代号、模型标识、等待原因、计划和实际耗时，以及固定错误分类与可能的 HTTP 状态码。它不包含 API Key、Authorization、Cookie、网址、会话标识、提示词、请求或响应正文、工具参数、加密历史、上游错误原文。

供应商代号和自定义模型代号在本次 YunSwitch 进程内可用于关联。常见的公开模型标识可直接显示。选用 **显示本机供应商名称** 时，只查询 YunSwitch 当前配置的供应商 ID 和名称，用于本机对照。复制仍仅含代号，供应商删除后也可查看已记录的代号。请求诊断与旧有用量日志分别展示，反馈问题时建议复制单条摘要。

## 记录范围

- 诊断通过桌面界面访问。代理的 HTTP 接口不提供诊断时间线。记录不写入文件或数据库。
- 同时跟踪最多 128 条活跃请求。超出后界面提示未跟踪数量，请求仍按原策略处理。
- 近期保留最近 64 条已结束的请求，最长可查阅 15 分钟。每条时间线最多保留 48 步，达到上限时保留起点和最近步骤。重启代理清空记录。
- 诊断覆盖进入本地代理处理器的 Claude、Claude Desktop、Codex、Gemini 和 Grok Build 请求。直接连接上游、健康检查和本地模型列表不在跟踪范围内。
- 请求恢复策略仍按各应用现有设置执行。原生 Codex 状态请求保留一次发送保护，已有输出或工具活动后不自动重放。加密历史兼容默认关闭。

现有恢复规则见 [Codex Responses 输出前错误恢复](CODEX-STREAM-RECOVERY.md) 与 [Codex Responses 兼容与自动重试](CODEX-RESPONSES-COMPATIBILITY.md)。源码和 Windows 构建的验证进度见 [开发路线](DEVELOPMENT-ROADMAP.md)。
